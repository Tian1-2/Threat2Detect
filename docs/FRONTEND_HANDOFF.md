# Threat2Detect 前端设计与实现交接

日期：2026-11-22。接收人：前端实现组员。目标：基于已经确定的视觉方向和稳定 JSON 契约，完成可交互的第一版桌面 Web 前端。本文与随附设计图可直接交给组员及其开发助手使用。

**当前决策：报告、Agent 活动、数据接入是三个全局入口；复核留在报告内。数据接入是全局独立工作区，进入后隐藏整个报告列表侧栏，并展示日志源、字段目录、ATT&CK 和 Sigma 版本。**

现有 Python 主控及规则执行已经可运行，但尚无正式 HTTP 服务、在线日志连接器、用户系统或持久化审核 API。先用本文附带的数据完成前端交互，通过数据适配层等待后端对接；不要改组员的模型接口或假装已连接生产系统。

## 2 产品定位和首版范围

用户围绕一篇报告完成：查看原文证据 → 检查 ATT&CK 映射 → 查看 Sigma 候选和条件分析 → 查看指定日志上的执行结果 → 浏览 Agent 工具轨迹 → 处理需要复核的内容。

全局数据接入回答：Agent 已经能读取哪些日志，这些日志有哪些事件类型和字段，采用哪个 ATT&CK 与规则库版本，哪些验证条件尚不具备。它不是 CPU 监控页，也不是实时 SIEM 大屏。

首版实现报告工作台、Agent 活动、数据接入，以及必要弹窗。设置只预留最小入口或显示“暂未配置”，不投入复杂账号、权限、协作、自动部署功能。规则生成是可选功能，默认关闭。

## 3 导航结构与路由

| 建议路由 | 最左全局栏 | 报告列表栏 | 主区域 |
|---|---|---|---|
| `/reports/:reportId` | 保留，报告选中 | 显示 | 行为表格与选中行为详情 |
| `/activity` 或 `/activity/:runId` | 保留，活动选中 | 显示 | 运行选择、实际工具轨迹、步骤详情 |
| `/data` | 保留，数据接入选中 | **完全隐藏** | 全局知识版本、日志源、字段与样例 |
| `/settings` | 保留 | 隐藏 | 最小设置或明确未实现状态 |

全局栏宽约 64–80px，使用图标加短标签。报告列表宽约 240–280px，支持搜索、选中态、长标题省略和滚动。不是把报告名放进全局窄栏。

进入数据接入时，释放报告侧栏占用的宽度，不留空白占位；不显示当前报告标题、报告搜索、案例列表或封存测试内容。返回报告时恢复之前的报告、运行、筛选和选中行为。不要让打开数据接入清空正在查看的分析结果。

数据页自身的来源选择和筛选是全局状态。只有显式点击“查看某报告的数据缺口”时才带入报告 ID，并提供清除筛选；不能默认将全局数据页绑定到最后一次打开的报告。

## 4 报告工作台

### 报告列表

每项显示报告编号、短标题、最近运行日期或无运行状态。AA25-266A、AA23-319A 是开发案例。AA24-193A 暂不审核、也不提供其正文、标注和答案给前端；最多保留一个不可展开的“封存测试”说明。

报告、运行和标注版本是不同对象。同一报告可以有多次运行。切换运行后使用那一次运行的 handoff、候选及结果，不要只按 `case_id` 把不同版本的行为数组混起来。历史运行保留原始输入哈希和知识版本。

### 行为表格

行为以 `behavior_id` 为稳定行键，不以命令文本或 ATT&CK ID 为键。同一技术可能对应多台主机或多次操作，不能按技术去重；不是所有行为都有命令，也不是所有行为都有映射。

工具栏支持搜索行为、命令、对象和技术 ID；按技术、审核状态、是否已分析筛选；支持分页。桌面默认 10 或 20 条每页，不为每条命令建立横向导航。

建议列：行为编号及摘要、主机或对象、ATT&CK 映射、规则分析概况、日志测试概况、审核状态。窄屏可以将主机并入行为摘要，但不丢失信息。多个映射用 `+N` 展开；无映射显示“尚未映射”。

一项行为可对应多条候选规则。概况只显示“未分析”“存在待审判断”“部分已测试”等派生信息，不从多个不同判断里任意挑一个当成该行为的总答案。详情逐候选展示真实判断。

### 行为详情

点击行打开右侧详情；主表保留。按顺序显示原文及页码/字符位置、行为事实强度、映射及理由、候选规则、逐条件分析、日志测试、复核操作。

规则详情展示 `supporting_conditions`、`missing_conditions`、`unknown_conditions`；可查看完整 YAML、出处、哈希。日志结果显示数据集、事件 ID、评估与跳过数量、执行器版本及限制，不只放一个绿色勾。

“查看相关 Agent 活动”跳转并筛选当前报告、运行、行为。复核在详情中完成，不另建导航页面。现有 `review_decisions.json` 是项目审核记录，尚无统一导入器或写入服务；前端初期可本地暂存并导出复核草稿，不能显示“已同步入库”或擅自把原 handoff 改成 confirmed。

新建/运行分析弹窗可包含报告文本或已准备的交接包、数据源选择、行为与调用预算、可选规则生成开关。PDF 自动提取和从 URL 抓报告不属于首版已具备能力。没有后端时，“运行”要说明尚未连接服务，或明确进入“查看演示运行”，不能伪造后台正在执行。

## 5 Agent 活动页

显示运行列表/选择、运行状态、已处理与未处理范围、模型调用/步数预算，以及实际发生的工具调用。支持按报告、行为、工具、错误筛选。

每步显示序号、人类可读动作、工具名、处理对象、执行结果。选中后展示输入摘要、工具观察、相关候选和事件引用；原始 JSON 默认折叠。不要把原始日志大段铺满，也不要展示或推测模型内部思维链。

| 工具 | 推荐中文标签 |
|---|---|
| `analyze_report` | 提取报告行为与技术映射 |
| `read_context` | 读取原文上下文 |
| `search_rules` | 检索候选规则 |
| `assess_candidate` | 分析规则条件 |
| `check_telemetry` | 核对日志与字段 |
| `test_rule` | 执行样例规则 |
| `generate_rule` | 生成候选规则 |
| `request_review` | 记录人工复核事项 |
| `finish` | 结束本轮自动处理 |

`trace.jsonl` 每行是一个主控步骤。显示实际顺序，不能写死为固定七步；报告理解、重复检索、生成或错误分支都可能改变轨迹。`specialist-NNN.json` 是 Sigma 局部轨迹，可在对应主控步骤下展开，不将局部步骤重复计为主控步骤。

模型选择理由作为“模型理由摘要 未核验”折叠显示。正文以工具观察为准：模型即使写“案例已解决”，若 `workflow_status` 为部分完成，页面也必须显示部分完成。

结束、预算耗尽、工具报错和人工复核分别显示。当前未实现暂停/恢复或服务级取消；可以预留控件，但必须禁用并注明原因，不能做空操作按钮。

## 6 数据接入页

### 知识与规则版本

位于全局页顶部，至少显示：

| 资产 | 首版显示内容 |
|---|---|
| ATT&CK | Enterprise 域、固定版本 v20.0、目录路径、SHA-256、是否可读取 |
| SigmaHQ | 固定 commit `05d1031f537e830b76da53bae2400c5814c89165`、库路径、可读取状态；列表可缩写为 05d1031f |
| 执行器 | 详情中展示 `sigma-offline-subset-0.1`、支持事件源/语法范围，不宣称完整 Sigma 兼容 |

“查看目录与哈希”“查看规则库”打开只读详情，不是跳转到服务器任意文件路径。当前页面不提供一键更新、切版本或下载最新库。后续版本管理要由后端统一校验，不能让前端私自修改锁定目录。

新运行记录实际采用的版本；已完成运行继续显示当时的版本，不能被全局“当前版本”覆盖。

### 日志源清单

展示来源名称、接入方式、日志类型、覆盖的主机/系统（未知则说明）、可用时间范围、状态、解析情况。当前只展示离线样本：LSASS_campaign_06 与 BITS download。数据平台连接入口明确标记“后续支持 尚未连接”，不伪造 Splunk、Elastic、真实企业主机等连接状态。

静态日志用“可读取”“历史数据”“时间范围待核对”，不用“实时在线”“最近同步正常”描述。采集时间与导入时间分开；来源没有时区或时间范围时显示未知，不依据文件修改时间猜采集时间。

### 字段目录

先选数据源，再按事件类型浏览。原始字段、标准字段、类型、脱敏示例、可用情况是必需列；支持字段搜索。Sysmon 1、10、11 的字段不能混成一张保证全部事件都具备的 schema。

OTRF 当前部分字段从 `Message` 文本提取，展示“Message 内 SourceImage → SourceImage”，不要谎称原始 JSON 有 `Message.SourceImage` 对象。实际标准化事件值位于 `fields` 字典。

区分“字段出现过”“非空值”“部分事件缺失”“完全未观测”“尚未统计”。缺失率若展示，必须来自当前筛选范围的统计并显示分母；未知统计显示 `—`，不填 0。字段类型来自样例推断时标记“样例推断”，不当成采集器保证。

### 事件样例和适配缺口

事件样例可查看标准化字段、原始位置 `raw_ref`、事件时间和 UID，默认脱敏；读取原始大文件交给后端，浏览器不自行访问本地绝对路径。

缺口按规则所需日志源/字段及逻辑分支说明。已有主控的字段检查是并集式保守检查，显示“字段缺失 需进一步核对分支”，不能直接写“该规则必然无法执行”。空召回不等于无规则，缺数据不等于行为没发生。

此页默认是全局视图，不放“当前 AA25 报告”的固定横幅；只有用户明确筛选关联报告时才显示其缺口。第一版没有全库自动可观测性分析器，不能仅按 ATT&CK 标签推导“已覆盖多少技术”。

## 7 状态和数据语义

以下维度独立，不能共用一个成功/失败字段。

| 来源字段 | 值 | 推荐展示 |
|---|---|---|
| 行为 `fact_status` | observed / attempted / inferred / unclear | 已观察 / 尝试 / 推测 / 不明确 |
| 行为及映射 `review_status` | draft / confirmed / disputed / insufficient_evidence | 待复核 / 已确认 / 有争议 / 证据不足 |
| 条件分析 `decision` | matches_procedure / partially_matches / does_not_match / insufficient_detail | 做法适用 / 部分适用 / 做法不适用 / 信息不足；旁边独立标注审核状态 |
| 日志 `status` | hit / miss / not_tested / incompatible_logsource / unsupported_rule | 命中 / 未命中 / 未测试 / 日志源不兼容 / 语法未支持 |
| 主控 `workflow_status` | completed_with_review / partial_with_review / budget_exhausted / controller_error | 本轮结束 待复核 / 部分完成 待复核 / 预算耗尽 / 主控异常 |

当前模型可能输出 `matches_procedure` 但仍是 draft；页面可显示“模型判断适用 待复核”，不能显示“已确认覆盖”。设计图中“运行用户未知”属于示意审核点，不可用它静默覆盖真实结果字段；人工修订另留记录。

`null` / 缺失表示尚无结论，显示“未分析”或 `—`；不是 `does_not_match`、`miss` 或已确认没有。`matched_event_uids: []` 单独不等于未命中，要读测试状态。预算用完也不是安全验证通过。绿色只用于对应维度的明确状态，不用一个大绿勾代表整条链路有效。

同一行为的审核状态与映射审核状态都需要确认，才能将该对记录标为确认样本。来源是报告表 ID 对齐的确认，不应包装成独立盲标答案。

## 8 现有数据对接位置

业务字段继续以 [INTERFACE_CONTRACT.md](INTERFACE_CONTRACT.md) 为准；前端增加适配层，不重定义 Python 模块契约。

| 页面信息 | 已有来源 |
|---|---|
| 报告、行为、引文、映射 | `handoff.json` |
| 候选规则、路径、版本、字段 | `candidates.json` |
| 规则条件判断 | `coverage.json` |
| 日志事件及字段 | `events.json`；日志源目录/统计需要后端或 fixture 汇总 |
| 实际执行与事件引用 | `rule_tests.json` |
| 汇总、未选中项、人审事项、生成结果引用 | `case_result.json` |
| 执行中状态和计数 | `state.json` |
| 主控活动 | `trace.jsonl` |

字段目录由现有标准化事件统计，当前 fixture 中只给有限样例事件的元数据，未复制 45 MB 日志。若某交互需要的样例值尚未提供，显示未加载或由后端补充，不凭空构造“真实事件”。

## 9 数据访问层与拟议接口

以下是建议的前端服务抽象或未来 API 形状，**不是已经存在的 HTTP 接口**。不强制框架；先把数据访问集中到 `services`/`adapters`，不要让组件直接依赖文件路径。

| 服务方法 | 将来可对应的接口 | 用途 |
|---|---|---|
| `listReports` | `GET /api/reports` | 报告列表 |
| `getReport` | `GET /api/reports/:id` | 报告元信息与版本 |
| `listRuns` / `getRun` | `GET /api/runs`、`GET /api/runs/:id` | 运行列表与状态 |
| `getRunArtifacts` | `GET /api/runs/:id/artifacts` | 规范业务结果 |
| `listRunSteps` | `GET /api/runs/:id/steps` | 轨迹分页及筛选 |
| `listLogSources` | `GET /api/log-sources` | 全局数据目录 |
| `getFieldCatalogue` | `GET /api/log-sources/:id/fields?event_type=10` | 事件类型相关字段 |
| `getEventSamples` | `GET /api/log-sources/:id/events` | 有界、脱敏的样例查询 |
| `listKnowledgeAssets` | `GET /api/knowledge-assets` | ATT&CK 与 Sigma 固定版本 |
| `startRun` | `POST /api/runs` | 后端接入后再启用真实运行 |
| `saveReviewDraft` | 后端确认后再定义 | 不提前发明与现有审核记录冲突的写入格式 |

浏览器不能直接执行 Python 或写仓库 JSON。首版服务实现读取 fixture；真 API 完成后替换服务层。轮询状态或 SSE 均需后端支持，不假装已有实时推送。不要把服务器路径作为公开 URL 或允许客户端传任意文件路径。

## 10 视觉与交互要求

沿用已经选定的浅色方案：冷白底、深靛文字、钴蓝主操作、浅紫技术标签、琥珀色未知/待复核；以留白、对齐、细分隔线组织内容，不叠多层卡片、不做黑客终端或无意义安全评分。

桌面以 1440–1600px 宽设计，正文 14–16px，最多两套字体；技术 ID 和代码可用等宽字体。报告/活动页的主内容自适应双侧栏，数据页只保留全局栏。较窄屏幕先折叠报告侧栏，将详情改为抽屉；表格允许局部横向滚动，不压到字无法阅读。首版不要求完整手机体验。

每个页面具备加载、空数据、失败、未分析和部分结果状态。长规则名/路径省略但可展开，错误原因可复制，筛选与分页联动。图标带标签或 tooltip，状态同时有文字，不只靠颜色。渲染报告和模型输出按文本处理，不能作为任意 HTML 注入。

## 11 实现顺序和验收

1. 实现三种布局状态：报告页、活动页、隐藏报告栏的数据页，确认切换后状态保留。
2. 通过 fixture 和适配层完成报告切换、行为搜索筛选分页、详情展开、候选切换。
3. 完成 Agent 实际轨迹、步骤详情、错误与停止原因展示，原始 JSON 折叠。
4. 完成知识版本、日志源切换、按事件类型的字段搜索、样例与缺口视图。
5. 补齐空/错/部分结果、导出和复核草稿交互，再替换为真实后端服务。

验收重点：

- 数据接入不出现报告侧栏，也不遗留空白；离开再返回报告时上下文保留。
- 多于一页行为时导航不膨胀，同技术不同行为不合并。
- 规则适用性、样例命中、审核状态分别展示，未知不改成否定。
- 一项行为多个候选可分别查看，不用单个状态掩盖差异。
- 活动页顺序与 trace 一致，模型理由不覆盖工具结果或规范状态。
- 未选中行为、预算耗尽和工具异常不显示为全篇成功。
- 日志字段随数据源/事件类型变化；缺失统计不伪造，离线数据不显示实时在线。
- ATT&CK 和 Sigma 显示固定版本与详情，历史运行保留原版本。
- 规则生成默认关闭，候选仍 draft，不显示自动部署或生产有效。
- 未实现的平台接入、运行、取消、审核保存明确禁用或解释，不做假成功。
- 不读取 AA24 封存内容，不改变模型、检测规则或既有 JSON 契约。
